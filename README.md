### 🧪 Yila AI — 持久化科研 Agent 工作台 &nbsp;<sub>⭐ 主力项目</sub>

<a href="https://yila.ai"><b>yila.ai</b></a> &nbsp;·&nbsp; 2026.06 至今 &nbsp;·&nbsp; <sub>源码私有</sub>

**在做一件什么事**

把「论文发现 → 文献综述 → 引用核验 → 科研图 / 学术海报」这些散落的单点能力，
组织成可复用的 **Research Agents / Playbooks**：一次研究任务可以连续跑几十分钟，
中途能暂停、能恢复、能追问，最终以 **Artifact（可下载的产物）** 交付，而不是留下一段聊天记录。
可以理解为「学术版 Manus」。

**工程上真正难的地方**

| 挑战 | 我的解法 |
| :--- | :--- |
| 长任务不能因为刷新、断网、发版就丢 | 基于 **Vercel Eve + Workflow World (PostgreSQL)** 的持久化会话，turn 级可重放；转录由服务端投影，浏览器关掉也照跑不误 |
| Agent 会执行花钱 / 不可逆的动作 | **HITL 确认门**：高成本或不可逆的工具调用先申请授权，用户拒绝则保证零副作用 |
| 要执行模型生成的不可信代码 | **默认拒绝出网的沙箱**，不下发任何 Provider Key；外部字节只能经受控的取件通道落盘 |
| Token 成本必须算得清 | **积分预扣 → 真实用量计量 → 结算入账**，失败/中断自动释放，全链路可审计 |
| Agent 行为不能靠「感觉」验收 | 27 个 Agent Eval + 仓库内 **382 个可复跑的门禁脚本**，发布走围栏 + 零残留排空 |
| 模型会挂、上下文会爆 | 多模型链路自动降级（GLM → Luna → DeepSeek）+ 长上下文压缩，30 万 token 处触发 |

**规模**：29 个研究 Skill · 42 个 Agent Tool · 21 个 Playbook · 52 个数据库迁移
邀请制 Beta 阶段 19 名用户跑出 **148 个 Research Run、935 个 Artifact**，平均每个任务沉淀 6.3 份资产。

**技术栈**：Next.js 16 · React 19 · TypeScript · PostgreSQL + Drizzle · Vercel Eve 0.47 · Cloudflare R2 · Docker / Dokploy 自托管
